## Technical mechanisms and transfer
Weight storage lower bound for P parameters at b bits is P*b/8 bytes; scales, metadata, alignment, workspace and resident pages add overhead. For conventional uniform transformer KV, bytes/token = 2*layers*KV_heads*head_dim*bytes_per_element. Example 24 layers, 8 KV heads, dimension 128, FP16 gives 96 KiB/token or 384 MiB at 4096 tokens, per sequence; illustrative, not a measurement. Hybrid or recurrent models need separate state formulas. Prefill and decode have different bottlenecks: prompt processing may benefit from parallel matrix operations while token generation often streams weights. Measure separately on ARM rather than extrapolate GPU results. PagedAttention uses logical-to-physical blocks and sharing to reduce wasted preallocation; paper reports GPU serving gains, not Pi results. On Pi compare fixed-capacity contiguous buffers, block pools, prefix reuse and recomputation; block indirection can cost CPU cycles. Never evict active state without explicit semantics. GQA/MQA are model architecture properties, not switches for arbitrary checkpoints. Quantized weights and KV are independent choices; avoid expanding compressed weights permanently to FP32. Tiled/fused kernels can reduce memory traffic; assess ARM vector support and backend delegation before building Rust kernels. Speculation adds draft-model footprint and verification cost; defer until single-model baseline exists. Distributed sharding may incur network overhead; not first priority.

### EDGE-MEM-01 → US-025: bounded admission and model residency (gap / extends US-007, US-020)
As Jack, I want a model and its request state admitted only within configured container capacity, so that one inference cannot kill the service or neighbouring workloads.
Setup: injected memory-budget provider, synthetic model estimates, host cache, finite cgroup-style limit. Action: load A, request B exceeding remaining capacity, then release A. Expected: explicit estimate with confidence/unknown fields, reserve before load, reject/defer or evict idle A according to policy; never evict referenced executor; retry succeeds after capacity available; concurrent admissions cannot double spend; failed loads release reservations. Report model identity, estimated weights/state/workspace, budget source, decision, actual peak when available and reason. CI: deterministic fake budget/loader with event assertions for reserve/reject/release and concurrent failure. Live: Linux cgroup v2 memory.max/current/peak/events with bounded container; check no OOM kill in controlled workload. Include process RSS separately from cgroup usage (file cache, other processes). Investigate ancestor limits, unlimited max, non-Linux provider, mmap page residency, allocator overhead and safety margin. Candidate paths: uie-ipc engine, runtime, loader metadata, uie-iv injection. Do not make preflight a guarantee against external memory pressure.

### EDGE-STATE-02 → US-027: bounded inference state (candidate extension US-004/010)
As Liz, I want a declared context and state budget, so long conversations cannot silently exhaust a small container. Given model architecture metadata and a configured state limit, compare short and long requests, two concurrent sessions, cancellation, and reuse. Accept within budget; reject or explicitly negotiate shorter context before execution; no silent semantic truncation. Release state after cancellation; reusable prefixes keyed by exact tokens, model version, position and relevant execution settings; isolate unrelated sessions. Test with a deterministic block allocator fixture or delegate to loader-native controls; assert state allocated/released, cache hits and rejection reason. Live GGUF: compare context settings against measured peak, verify same prompt/tokenizer and deterministic output where supported. Inspect llama.cpp binding for n_ctx, KV types, batch and session controls first; if existing support suffices document it, avoid duplicate cache implementations. Alternatives: contiguous cap, paged pool, recompute, model-supported sliding window. Unknowns: state ownership across executor/session, quantized KV support and prefix isolation.

### EDGE-BENCH-03 → US-028: constrained benchmark and quantization acceptance (extend US-023 and US-010)
As Pete, I want equivalent, repeatable measurements of model variants and runtime configurations so that smaller workloads can be chosen by quality and cost rather than file size. Given fixed model family/revision, tokenizer, prompts, generation cap, sampler/seed and hardware profile, compare supported GGUF variants on the same container. Record model hash, loader/backend revision, threads, affinity/quota, RAM limits, context, cold/warm definition, load time, TTFT, decode throughput, peak RSS and cgroup usage, error/oom counts, and task quality. For classification measure accuracy/F1 against labels; for generated text use fixed task assertions or declared judge, not identical tokens across quantization. Separate missing measurements from zero. CI stub traces assert schema, units, provenance and rejection of incomparable runs. Live: repeat at least three times, report median and spread; thermal state and throttling recorded where possible; report quality and resource tradeoffs, no universal speed threshold. Existing ExecutionRecorder/InferMetrics and JSONL are the extension surface. Investigate whether llama.cpp exposes measured peak and token timing; retain external measurement harness if needed.

### EDGE-ARM-04 → US-029: capability-aware optimized execution (candidate extension US-003/005/006)
As Pete, I want supported ARM kernel paths selected safely, so small CPUs benefit without losing numerical correctness or portability. Given an operation supported by scalar and optimized backend, compare deterministic fixture outputs under declared tolerance, odd shapes/tails and unsupported CPU features. Assert dispatch event with backend/kernel/precision and reason; unavailable fast path falls back or returns explicit unsupported error, never illegal instruction. Validate integer paths exactly where mathematical contract permits; floating-point tolerances per operation and precision. Live Pi 4/Pi 5 measure kernel and end-to-end cost, memory and thermal effects. Investigate existing llama.cpp/ONNX delegation before adding kernels; NEON and optional dot-product support must be detected rather than assumed. Fusion and scratch-buffer reuse are alternatives, not required implementation. Upstream NVIDIA mechanisms motivate memory movement reduction; actual ARM implementation research remains pending.

## Suggested experimental matrix
Illustrative container memory limits 256/512 MiB (1 CPU), 1 GiB (2 CPUs), 2/4 GiB (4 CPUs), constrained by host capacity. Start with stub, tiny classifier and small GGUF; unsuitable combinations are expected admission failures, not benchmark failures. Compare Pi 4/5 ARM64, identical runtime/model revisions, storage medium, OS/kernel, container configuration and cooling. Record warm-up separately; avoid dropping global caches on shared host. Record wall time and cgroup CPU throttling, optionally energy with external measurement. No tests or Pi benchmarks executed in this research pass.
