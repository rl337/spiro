## Technical mechanism and tradeoffs
The upstream harness serializes control/candidate/control experiments with flock, streams server usage counts instead of treating transport chunks as tokens, tracks first token with monotonic time, tests long-context retrieval using seeded hidden codes, and logs failed or looping generations. It uses at least six decode samples and compares medians against adjacent controls to reduce thermal and temporal drift. A reported GPU speedup is not a Pi forecast. On ARM CPU, memory bandwidth and effective bytes read per generated token can give a rough upper bound (B/W, bytes/s divided by bytes/token); MoE, caching and speculation change W, and compute or I/O can lower throughput further. Do not call this a measured ceiling. Measured TTFT includes queue/transport time unless instrumented separately; prompt tokens divided by TTFT is an end-to-end proxy, not pure prefill. Decode throughput excludes first token and uses elapsed time after first token; aggregate concurrency uses common wall interval rather than summing nonoverlapping rates. If batched chunks lack per-token timestamps, report limitation. The source's long-context gate checks exact retrieval, not general task quality; retain task-specific checks too. Its fixed 3% regression margin and six samples are source choices, not universal statistical proof. For Pi thermal governor, CPU frequency/throttling, cgroup quota and storage effects, record conditions and reject invalid comparisons; don't require privileged host access or turn off thermal protections.

## Candidate EDGE-BENCH-03 amendment: trustworthy comparison
As Pete, I want controlled paired performance experiments to reject measurement artifacts, so I can select optimizations that really help a small Pi container without hiding correctness regressions.
* Freeze workload IDs, model/tokenizer/quant hashes, backend version, sampling and generation cap, CPU quota/threads, effective memory cap and cold/warm policy. Only declared variable(s) may change. Test panel includes small classifier and GGUF; use modality-specific metrics, not tokens for classifier outputs.
* CI injected clock/trace fixtures: baseline 100, candidate 108, following baseline 110 (illustrative rates). Report drift/inconclusive, not unconditional win. A candidate 120 with both controls 100 and all gates passed can be eligible under predeclared margin and uncertainty policy; not a statistical claim from one sample. Missing control, failed request or missing counters = incomplete/not comparable. Preserve raw records, paired IDs and reason codes.
* Feed a fake stream where 3 chunks contain 9 generated tokens; use tokenizer/server usage, not chunk count. If timing or counts missing, report unknown, not zero. Warm cache-hit request must not be classified as cold prefill. Assert trace/event fields, units and calculation boundaries.
* Resource/correctness negative controls: faster output loops or fails a known answer, exceeds memory cap, or retrieval code at a supported context depth is wrong. Do not promote; retain failed data. Positive control preserves output validity and resource cap. Restart halfway through bracket resumes with stable trial IDs and reruns missing control; no duplicated samples or incomplete bracket silently accepted.
* Live Pi4/Pi5 ARM64 container: same model image and workload, repeat interleaved A/B/A cycles, predeclared confidence or robust spread, cap and cancellation, report cold/warm separately, peak RSS and cgroup memory/CPU, temperature/frequency if accessible. Use small representative supported contexts rather than importing GPU 256K settings. Compare candidate quality against held-out examples. Record raw traces, no numerical performance target until baseline measured.
